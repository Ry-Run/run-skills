# Ace Tool Skill

## 快速上手

目标：先用语义搜索回答“这段逻辑到底在哪”，再决定读哪个文件、改哪个点。

主入口：
- `mcp__ace_tool__search_context`

参考资料：`skills/ace-tool/references/ace-tool_zh.md`

## 适用场景

- 不知道实现分布在哪些文件里。
- 需要跨文件理解某个功能、Bug、流程或子系统。
- 改代码前想先找类似实现或现有模式。
- 需要快速找到相关测试、handler、service、集成点。

## 不适用场景

- 已知精确标识符，想查全部引用，例如某个函数名。
- 已知文件名，想直接定位文件。
- 文件范围已经很小，直接读文件更快。

这类场景应在 Ace Tool 缩小范围后，切回 `rg`、IDE 搜索或直接读文件。

## 推荐工作流

1. 用一句自然语言描述“行为 / 流程 / 目标”，必要时补关键词。
2. 如果准备改代码，把相关类、方法、属性、测试一起写进同一个查询。
3. 先读返回的文件路径与片段，确认真正相关位置。
4. 再使用精确读取和定点编辑工具。

## 查询写法

- 优先写“行为”，不要只写标识符。
- 结尾补关键词有助于召回。
- 如果需要测试，直接在查询里说明。
- 能放在一次查询里的关联对象，就不要拆成很多小查询。

## 约束与红线

- 必须传真实项目根目录。
- 只要文件归属不清楚，编辑前就先跑一次 Ace Tool。
- 语义匹配不是事实本身，最终仍要靠直接读文件确认。

# PPT 工作流参考

本参考基于 Linux.do 主题 `1782304` 中讨论的工作流思路整理。

## 阶段 1：先定义这份 PPT

先逼自己回答这些问题：

- 受众是谁？
- 希望他们看完后得到什么结论或行动？
- 这份 PPT 的语气是什么：说服、分析、教学、汇报，还是叙事？
- 预计需要多少页？

## 阶段 2：先生成 JSON 大纲

建议大纲结构：

```json
{
  "title": "PPT 标题",
  "audience": "目标受众",
  "goal": "演示目标",
  "slides": [
    {
      "id": 1,
      "section": "开场",
      "title": "页面标题",
      "goal": "这一页必须完成什么任务",
      "key_points": ["要点1", "要点2"],
      "visual_hint": "图表 / 时间线 / 对比 / 核心结论"
    }
  ]
}
```

## 阶段 3：按页补资料

每一页或每个章节至少补这些内容：

- 支撑事实
- 来源链接
- 案例或示例
- 可用视觉素材或数据素材
- 还没回答清楚的开放问题

只要事实有缺口，就不要急着进最终页面。

## 阶段 4：生成逐页策划稿

把每一页展开成：

- 页面核心信息
- 支撑证据
- 推荐页面结构
- 演讲者意图

示例提示词骨架：

```text
请把这份 PPT 大纲展开成逐页策划稿。
每一页都写清楚：
1. 核心信息
2. 支撑证据
3. 推荐视觉结构
4. 演讲者备注意图
要求每页只承担一个清晰任务。
```

## 阶段 5：生成 SVG 页面

默认每页一份 SVG，统一使用 16:9 画布。

默认要求：

- 整份视觉系统一致
- 信息层级清晰
- 字体和留白达到演示文稿级别
- 页面结构要服务该页目标，而不是套模板

示例提示词骨架：

```text
请为第 {n} 页生成一份 SVG 页面。
使用 16:9 演示画布。
本页目标：...
关键要点：...
建议结构：...
不要做成文字墙。
```

## 阶段 6：组装 PPT

如果接受 SVG 导入工作流，就以每页 SVG 作为视觉定稿基础组装 PPT。若最终交付要求原生可编辑幻灯片，则在 SVG 定稿后，再进入 PPT 工具重建或微调。

# PPT 工作流生成

## 快速上手

目标：不要一上来就逐页硬写幻灯片，而是先建立稳定的结构化工作流，再产出最终页面。

参考资料：
- `skills/ppt-workflow-builder/references/ppt-workflow.md`
- `skills/ppt-workflow-builder/references/ppt-workflow_zh.md`

## 最适合的场景

- 演讲稿、汇报 PPT、客户提案、融资 Deck、教学课件、方案展示。
- 原始材料很散，需要先梳理叙事结构，再生成页面的任务。
- 需要把“大纲、研究、策划、页面生成”拆成多个阶段的场景。
- 接受先生成 SVG 页面，再导入 PPT 或据此继续制作正式演示文稿的场景。

## 核心工作流

1. 先定义这份 PPT：
   - 明确受众、目标、语气、期望页数。
   - 明确整份演示要证明的主线。
2. 先产出结构化大纲：
   - 用 JSON 形式写出章节、每页目标、每页核心论点。
   - 在大纲稳定前，不要开始做最终页面。
3. 按章节做资料研究：
   - 技术主题优先用 `context7` 查官方文档、API、标准资料。
   - 实战实现、GitHub 示例、issue、代码证据优先用 `ref-skill`。
   - 更宽泛的研究、方案对比、行业背景、最佳实践、非技术材料优先用 `grok-search`。如果知道当前 Grok 模型，必须说明。
4. 把大纲展开成策划稿：
   - 对每一页明确：核心信息、支撑证据、页面形态、演讲意图。
   - 不能推动主线的页面就删掉。
5. 生成最终页面：
   - 默认每页单独生成一份 SVG，统一使用 16:9 画布。
   - 页面要达到“可演示、可导入、可继续编辑”的质量，而不是临时草图。
6. 组装 PPT：
   - 如果允许 SVG 导入工作流，就把 SVG 页面导入演示软件。
   - 如果后续必须做原生 PPT 深度编辑，则把 SVG 页面作为视觉定稿基础，再在 PPT 工具里重建或微调。

## 工作文件

建议保持一条稳定的中间产物链：

- `deck-outline.json`：确认后的结构化大纲
- `deck-research.md`：研究资料、事实、引用和补充说明
- `deck-plan.md`：逐页策划稿，写清每页信息与版式意图
- `slides/slide-01.svg`、`slides/slide-02.svg`：最终页面资产

不要从主题直接跳到最终页面。大纲和策划稿本身就是这条工作流的一部分。

## 提示词模式

不要用一个超长大 prompt 一次性赌出整份 PPT，优先分阶段提示：

1. 先确定受众、目标、语气、页数。
2. 再生成 JSON 大纲。
3. 再补齐每一页缺失的资料和证据。
4. 再产出逐页策划稿。
5. 最后生成 SVG 页面。

参考文件里放了每个阶段的提示词骨架，可以按需调用。

## 约束与红线

- 在主线没有明确之前，不要先做页面装饰。
- 大纲没有确认前，不要提前生成最终页面。
- 不要让每一页都堆满文字；每页只能承担一个清晰任务。
- 不要把研究笔记直接粘成页面文案，要改写成演示表达。
- 不要默认用“一次性大 prompt”生成整份 PPT，分阶段流程更稳定。
- 如果某一页事实不足，回到研究阶段补资料，不要硬编。

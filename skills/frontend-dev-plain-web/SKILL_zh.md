# 前端开发（纯 CSS、HTML、JS）

## 快速上手

目标：用最小必要流程交付纯前端页面，而不是把研究、实现和验证临时拼凑在一起。

## 最适合的场景

- 落地页、静态页、简单交互页。
- 明确要求保持纯 HTML、CSS、JavaScript 的任务。
- 从需求、参考图、参考站点或粗略想法直接进入代码实现。
- 完成前需要做完整浏览器验证的页面工作。

## 推荐工作流

1. 先收敛页面目标、约束和关键交互。
2. 资料查证按这个顺序走：
   - `context7`：官方文档、API、标准用法。
   - `ref-skill`：GitHub 示例、issue、实战代码。
   - `grok-search`：原理解释、方案对比、最佳实践、难查的技术问题，以及所有非技术内容。若知道当前 Grok 模型，必须明确说明。
3. 如果环境里可用，先用 `frontend-design` 约束页面结构与视觉方向。
4. 如果环境里可用，在生成 UI 时带上 `uncodixfy`，避免落入泛化 AI 页面风格。
5. 本地实现与文件操作交给 `desktop-commander`。
6. 主流程验证优先使用 `playwright-skill`。
7. 行为仍不清楚或需要深挖时，再进入 `chrome-devtools` 做调试。
8. 只有确实需要响应式适配时，再用 `adapt`。
9. 只有页面主体稳定后，再用 `polish` 做收尾。

## 验证清单

- 页面能正常加载。
- 核心交互可用。
- 要求覆盖的视口下布局正常。
- 必要时检查明显的 console 或 network 问题。

## 约束与红线

- 默认保持轻量，不要一上来就引入任务管理、Figma、GitHub、Vercel 等无关 skill。
- 主线验证优先 `playwright-skill`，深度诊断再用 `chrome-devtools`。
- 除非用户明确要求，否则不要把纯前端页面升级成框架项目。
- 只有在确实能提升结果时，才引入可选设计类 skill。
